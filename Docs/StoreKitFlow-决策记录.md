# 已确认决策

日期：2026-11-05。依据：用户确认前 1–7 项，并明确第 5 项的 Pro 行为、当前没有自有账号、暂时不需要后端验证、无需旧接口兼容。

| 项目 | 本轮执行口径 |
|---|---|
| 名称 | 模块和包 `StoreKitFlow`；对外入口 `StoreClient`；工程 `StoreKitFlowExample` |
| 发布 | 2.0 破坏性重构；不保留旧代理/闭包管理器适配层；远端、tag、trunk 尚不改动 |
| 技术 | Swift 6，iOS/iPadOS 17+；macOS 14+ 核心；本机 Xcode 27.2 验证 |
| 商品 | 四类标准内购；新型组合商品/Advanced Commerce 明确返回不支持并留作条件任务 |
| Pro | 显式 `entitlements: ["pro"]`；多来源取有效并集；无 Pro 等级推断 |
| 自动续订 | 有效周期、有效试用、有效宽限期保留；纯重试期、到期、撤销不授权该来源 |
| 取消 | 关闭自动续订不提前删除本期权益；退款提交不提前撤销 |
| 非续订 | 按每商品日历期限，默认从本次购买日起算；可显式 `stacks: true` |
| 消耗品 | 不直接授予 Pro；本地持久化额度；退款扣除剩余可用额度并记录已花费差额，不形成负余额 |
| 账号 | 当前没有自有账号，默认 `appAccountToken = nil`；不生成设备 UUID 冒充用户账号 |
| 后端 | 当前无网络验证接口；保留 `TransactionValidator`、`DeliveryHandler`、`OfferSigner` 三个注入点和签名证据 |
| 家庭共享 | 接受 StoreKit 已验证的共享来源，可在配置中关闭；不推断真实家庭成员身份 |
| 迁移 | 本轮不写旧 API 兼容层，不改生产商品 ID；旧 tag 由仓库历史保留 |

预留后端接口值得保留：不会增加当前 App 的服务器依赖，却能在未来需要跨设备消耗品余额、账号权益或促销签名时接入。新账号系统的绑定、退出、转移和服务端协议届时应单独设计，不能直接把当前 nil token 交易绑定到任意登录用户。

确认范围不包括部署服务器、创建 App Store Connect 商品、改变 Apple 账号或证书、发布商店、重命名远端仓库。真实沙盒需要应用自己的商品和测试账户，验收记录会明确哪些尚未验证。
